Zentriz Genesis

Guia de Configurações

Como preparar sua conta para gerar, publicar e operar aplicações com autonomia total.

O Genesis constrói o seu produto de ponta a ponta — da especificação ao código, testes, publicação e monitoramento. Para que a fábrica trabalhe com as suas próprias credenciais (seu provedor de IA, sua nuvem, seus repositórios), há um conjunto de Configurações na plataforma. Este guia explica cada uma: o que é, para que serve e como configurar.

Todas ficam no menu lateral, dentro do grupo Configuração (ícone de engrenagem). As três primeiras são essenciais para um bom uso da plataforma — comece por elas, nesta ordem.

As três configurações essenciais

Sem elas o Genesis ainda funciona com os recursos de cortesia da Zentriz, mas você não terá autonomia completa — e a publicação automática do seu produto pode não acontecer.

1. LLM / IA Essencial

O que é: define qual provedor e modelos de Inteligência Artificial o Genesis usa para raciocinar e gerar o seu código.

Para que serve: dá a você controle e previsibilidade de custo e capacidade — a fábrica passa a consumir a sua conta de IA, com o modelo que você escolher. Você define 1 provedor Padrão e até 3 Contingências (usadas automaticamente se o principal falhar).

Provedores suportados e credenciais:

ProvedorCredenciais necessárias
AWS BedrockAccess Key ID, Secret Access Key, Região
OpenAI (GPT)API Key
Anthropic (API direta)API Key (sk-ant-…)
Azure OpenAIAPI Key, Endpoint, Deployment name, API version

Como configurar:

Menu Configuração › LLM / IA → Adicionar → escolha o provedor → informe as credenciais → escolha o Modelo principal (e, opcionalmente, um modelo de fallback para retrabalho/QA e um modelo dedicado ao Cyborg, a etapa final de lapidação e entrega) → salvar. Nos limites globais você pode definir projetos simultâneos e cota diária de tokens.

Se não configurar: o Genesis usa o provedor padrão da Zentriz (pool de cortesia) e consome os seus créditos de cortesia. O build não quebra, mas você não controla modelo nem custo.

2. Cloud Deploy Essencial

O que é: as credenciais da sua nuvem, para o Genesis publicar o produto automaticamente após a geração do código.

Para que serve: ao aceitar um projeto, o Genesis injeta essas credenciais como secrets no repositório e gera o fluxo de deploy (deploy.yml) — o seu app sobe sozinho. Suporta 1 conexão Principal + fallbacks. As credenciais são criptografadas (AES‑256‑GCM).

Provedores suportados e credenciais:

ProvedorCredenciais necessárias (obrigatórias)
AWS (ECS Fargate / ECR)Access Key ID, Secret Access Key, Região — (opc.: ECR Registry, ECS Cluster)
Azure (Container Apps / ACR)Client ID, Client Secret, Subscription ID, Tenant ID — (opc.: Resource Group, Container App)
GCP (Cloud Run / GCR)Service Account Key (JSON), Project ID — (opc.: Região, Service name)

GCP: a Service Account precisa dos papéis Cloud Run Admin, Storage Admin e Artifact Registry Writer.

Como configurar:

Menu Configuração › Cloud Deploy → Conectar Cloud → escolha o provedor → preencha as credenciais → use Testar para validar antes de salvar.
Se não configurar: o repositório é criado e o código é enviado, mas não há deploy automático — nenhum secret é injetado e o fluxo de publicação não é gerado. Você teria que publicar manualmente.

3. GitHub Essencial

O que é: a conexão com o GitHub App da Zentriz instalado na sua organização, para o Genesis (e o Auto Care) criarem repositórios, fazerem commits e abrirem PRs no seu GitHub.

Para que serve: é o que permite entregar o código no seu repositório. Sem ela, o produto é gerado mas não chega ao GitHub.

Campos necessários:

  • Installation ID — obtido em github.com/organizations/<sua-org>/settings/installations.
  • App ID — identificador do App.
  • Chave Privada — o conteúdo do arquivo .pem do App (criptografado no servidor antes de gravar).

Como configurar:

Menu Configuração › GitHub → Conectar GitHub App → informe Installation ID, App ID e a Chave Privada → salvar. A tela passa a mostrar a organização, os repositórios autorizados e a data de instalação.
Atenção — permissão de criação de repositório: o GitHub App precisa da permissão “Administration: Read & write” na sua organização. Sem ela, a criação do repositório falha com erro HTTP 403 “Resource not accessible by integration” e o produto — mesmo 100% pronto e com build verde — não é publicado. Se isso acontecer, o administrador da organização deve conceder essa permissão ao App (e reprocessar o projeto). Sem o App instalado, o Genesis nem cria o repositório e avisa no histórico do projeto.

As demais configurações

Opcionais ou específicas — configure conforme a necessidade do seu produto e da sua operação.

Deployments

Lista e gerencia as publicações: Preview S3 (estáticos efêmeros, com expiração — excluíveis aqui) e Backend durável (runtime monitorado pelo Auto Care, apenas visualização). Configuração › Deployments

Skill Store

Curadoria do conhecimento dos agentes — os fragmentos que compõem o comportamento de cada papel (Dev, QA, PM, DevOps, Engenheiro, Cyborg). Administradores podem promover, depreciar ou restaurar habilidades. Configuração › Skill Store

Ferramentas UI/UX (Figma / Canva)

Conecta suas contas de design para o Genesis extrair definições visuais ao especificar telas. Figma: Access Token (figd_…) e Team ID. Canva: token OAuth ou conexão em 1 clique. Até 6 conexões, criptografadas. Configuração › Ferramentas UI/UX

Telegram

Vincula sua conta ao bot @zgenezis_bot para receber notificações e controlar pipelines pelo celular. A vinculação é por usuário, via um código temporário. Configuração › Telegram

Runtime Config (administradores)

Ajustes finos de execução por tenant: timeouts por agente, limites de iteração e limites de tokens. Cada parâmetro pode sobrescrever o padrão global; “restaurar” volta ao padrão. Configuração › Runtime Config

Usuários

Gestão dos membros da sua organização e seus papéis (user, tenant_admin). Convide, edite papéis e remova acessos. Configuração › Usuários

Plano e uso

Mostra o plano atual, projetos ativos versus limite e o saldo do crédito de cortesia. Informativo. Configuração › Plano e uso

Ordem recomendada

1. GitHub — conecte o App (com permissão de criação de repositório) para o código ser entregue.
2. Cloud Deploy — conecte sua nuvem para o produto subir sozinho.
3. LLM / IA — aponte seu provedor de IA para controlar modelo e custo.
4. Ajuste o restante (UI/UX, Telegram, Usuários) conforme a necessidade.
